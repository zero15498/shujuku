# UI v2 Toast / 通知方案

> 状态：当前权威方案。2026-05-21 的第一轮 v2 toast 试做已回滚；当前代码已按收窄后的方案重新落地 v2 toast。新 toast 只作为 v2 主界面打开期间的面板内短反馈，不接管旧 `showToastr_ACU`，不做常驻全局路由。
> 日期：2026-05-11；修订：2026-05-21；落地校准：2026-05-21。
> 范围：定义 v2 面板内 toast 的产品语义、调用边界、视觉约束与迁移顺序；不作为旧 toast 入口路由、旧 runtime 全局反馈或旧 UI 下线的架构源。

## 1. 背景

当前 v2 中部分页面使用局部 `AcuMessage` 显示操作结果。例如更新参数页的普通参数实时保存后，曾把“设置已保存”显示在“填表提示词”面板里。这暴露了两个问题：

- “已保存”是操作结果，不属于某个业务面板的长期状态。
- 实时保存字段如果每次都弹成功提示，会形成噪音，用户最终会忽略真正重要的反馈。

数据库已有运行日志页。通知体系应与日志流分工，而不是用 toast 承担所有错误细节。

## 1.1 设计修订（2026-05-21，第一轮试做已回滚，当前已重新落地）

`SUN-1` 原文里的“下线旧 UI 前”指的是：v2 主界面已经覆盖主要功能，只剩 toast / confirm / 可视化表格编辑器等少数表层能力仍沿用旧实现的时间点。当前已经进入这个时间点，因此 v2 toast 可以先于旧 UI 删除重新设计；2026-05-21 后实现层不保留前一轮试做。

第一轮试做失败的根因是目标过大：试图用新 toast 全面替代旧 toast，并向旧 runtime / 旧 UI 的全局反馈扩张。当前重做已收窄为 **v2 主界面打开时，面板内操作产生的短反馈**：

- 已重新新增 `src/presentation-v2/stores/toast-store.ts` 与 `src/presentation-v2/components/_lib/AcuToastViewport.vue`。
- viewport 挂在 `App.vue` 内，跟随 v2 主界面生命周期和 host document；v2 主界面关闭时清空并不显示新 toast。
- `src/presentation-v2/**` 不 import `src/presentation/theme/toast`、`showToastr_ACU` 或旧 confirm 模块。
- 旧 runtime / 旧 UI 暂时继续使用旧 `showToastr_ACU`；本方案不改造旧入口、不做 fallback 路由、不保证 v2 关闭时仍有新 toast。
- custom-confirm Vue 化仍属于后续阶段；不要把回滚前的试做实现视作当前代码状态。
- visualizer / 可视化表格编辑器仍是单独迁移项，不阻塞 v2 toast。
- 新 UI 设置页内的用户操作默认走 v2 toast；需要就地修正的表单校验、持续状态仍保留 `AcuMessage`；旧 visualizer 本体反馈作为单独迁移项处理。

本文件覆盖 v2 面板内 toast 的产品语义。旧 `showToastr_ACU` 调用面、旧 runtime 全局反馈、旧 toast 删除与全项目 confirm 替换仍属于旧 UI 下线清理阶段，不在本方案中处理。

### 1.2 试做记录（2026-05-19，已回滚）

v2 内部 custom-confirm 曾试做 Vue 化，但实现已回滚；以下只保留目标形态：

- 后续可重新新增 `src/presentation-v2/stores/confirm-store.ts` 与 `src/presentation-v2/components/_lib/AcuConfirmViewport.vue`。
- 后续 viewport 可挂在 `App.vue`，不复用旧 `presentation` confirm 模块。
- `src/presentation-v2/**` 内删除、覆盖、清空、丢弃未保存修改等确认入口最终应改为 v2 异步确认。
- 成功后的 toast 仍按本文件第 3 节分类：结果明显的列表删除不额外 toast；显式导入 / 导出 / 保存保留短 toast；执行类与长任务保留业务区域反馈。

### 1.3 当前落地修订（2026-05-20）

收窄 `AcuMessage` 与执行类操作的边界：

- `AcuMessage` 不再承载“当前执行区最后一次任务结果”。
- 执行类操作的开始、完成、失败、取消等一次性结果优先使用 toast。
- 面板内只保留用户需要持续关注、持续修正或持续确认的状态，例如“上一次测试失败，请检查配置或查看运行日志”。
- 长任务允许在执行区展示进行中状态、进度和阻塞原因；结束结果仍按 toast 处理，只有需要用户后续处理的状态才留在面板布局。

### 1.4 非目标（2026-05-21 修订）

本轮重做不处理全局 toast 路由：

- 不把 `showToastr_ACU(...)` 改成新 toast 路由器。
- 不新增独立常驻 Vue toast layer。
- 不要求数据库主界面关闭时，后台运行流程仍显示新 toast。
- 不迁移旧 toastr 的 HTML 字符串、jQuery handle、停止按钮等兼容约定。
- 不把 toast 作为推进 [07-architecture.md](07-architecture.md) 中完整 feedback port / runtime 分层的前置任务。

[08-toast-routing-consolidation.md](08-toast-routing-consolidation.md) 记录的是已暂停的全局路由方案，只作为历史备选与反例参考；当前实现应以本文为准。

## 2. 设计原则

### 2.1 不为实时保存制造噪音

实时保存的普通配置不默认 toast。控件值本身就是状态反馈。

适用例：

- 数字字段失焦保存。
- toggle / checkbox 切换。
- 下拉选择变更。
- 标签筛选规则输入。
- 世界书条目勾选。

这些操作只在失败时给前台短反馈，成功不提示。

### 2.2 Toast 只表达短、瞬时、跨页面一致的结果

Toast 用于“用户需要立即知道，但界面状态不一定自然说明”的结果。文本必须短。

适用例：

- 显式保存 dirty 草稿：`提示词已保存`、`预设已保存`。
- 导入结果摘要：`已导入 3 个预设，覆盖 1 个同名预设`。
- 导出结果：`已开始导出` 或 `导出完成`。
- 失败摘要：`操作失败，详情见运行日志`。

不适用例：

- 长错误堆栈。
- 多段业务说明。
- 表单校验说明。
- 可直接从当前页面看出的新建 / 重命名结果。

### 2.3 日志是错误详情来源，UI 是短反馈入口

警告和错误应写入运行日志流，包含完整上下文、错误对象和必要堆栈。

前台 UI 仍需要最小反馈：

- 操作失败但原因较复杂：toast 显示 `操作失败，详情见运行日志`。
- 用户可立即修正的输入问题：局部 `AcuMessage` 直接显示，例如 JSON 格式错误、提示词缺少必要占位符。
- 长耗时执行失败：执行区域显示短状态，详情进运行日志。

日志不是前台反馈的替代品；它是详细诊断来源。

### 2.4 危险操作以确认弹窗为主

删除、覆盖、清空等危险操作，首要保护是确认弹窗。成功后是否 toast 取决于结果是否明显：

- 列表立即少一项，且上下文不丢失：可不提示。
- 删除后自动切换当前项、关闭抽屉或结果不明显：可短提示。
- 删除失败：toast 短提示 + 日志详情。

### 2.5 执行类操作区只保留持续状态

执行类操作不套用统一“已保存”。但执行区也不应该长期展示一次性结果。开始、完成、失败、取消等短生命周期结果使用 toast；执行区只保留当前仍然影响用户下一步操作的状态。

适用例：

- 手动填表：进行中进度可在执行区或任务 toast 中呈现；完成 / 失败 / 取消用 toast。
- 正文替换测试：测试失败用 toast；面板可持续显示“上一次测试失败，请检查配置或查看运行日志”。
- 重新优化：是否替换成功、有多少建议用 toast；若失败导致当前配置不可继续使用，面板保留可修正状态。
- 交火构建 / 归档：进行中、等待、阻塞原因可在执行区显示；结束结果用 toast。

失败详情进运行日志；面板内文案应描述用户还需要关注什么，而不是复述刚刚发生了什么。

## 3. 操作分类规则

| 操作类型 | 成功 toast | 失败前台反馈 | 详情位置 | 备注 |
|---|---|---|---|---|
| 实时保存普通参数 | 否 | 是 | 运行日志 | 控件状态已表达成功 |
| 显式保存 dirty 草稿 | 是 | 是 | 局部 message / 运行日志 | 需要“未保存 -> 已保存”闭环 |
| 新建 | 通常否 | 是 | 运行日志 | 若直接进入编辑或列表可见，不提示 |
| 重命名 | 通常否 | 是 | 运行日志 | 名称立即变化即可 |
| 删除 | 视情况 | 是 | 运行日志 | 确认弹窗是主要保护 |
| 导入 | 是 | 是 | 局部 message / 运行日志 | 需要摘要数量、覆盖数量 |
| 导出 | 可选 | 是 | 运行日志 | 下载行为明显时可不提示 |
| 执行业务任务 | 是 | toast + 必要时局部持续状态 | 运行日志 / 当前面板 | 一次性结果不进入面板布局；需要用户后续处理的状态才保留 |
| 表单校验 | 否 | 局部显示 | 当前表单 | 用户需要立即修正 |

## 4. 推荐架构

### 4.1 v2 toast store

新增 v2 专用通知 store，例如：

- `src/presentation-v2/stores/toast-store.ts`

状态建议：

- `items: ToastItem[]`
- `ToastItem`: `id`、`kind`、`text`、`createdAt`、`durationMs`、`dismissible`、可选 `action`

动作建议：

- `success(text: string, options?)`
- `info(text: string, options?)`
- `warning(text: string, options?)`
- `error(text: string, options?)`
- `dismiss(id: string)`
- `clear()`

默认时长：

- success / info：约 2200-3000ms。
- warning：约 4000ms。
- error：约 5000ms 或手动关闭。

### 4.2 v2 渲染位置

新增全局组件，例如：

- `src/presentation-v2/components/_lib/AcuToastViewport.vue`

挂载位置：

- 由 v2 主界面的 `App.vue` / root shell 内 viewport 承载。
- viewport 与 v2 主界面同生命周期；主界面关闭时，新 toast 不再显示。
- 不复用旧 `#toast-container`，不挂载独立常驻 toast layer。

视觉要求：

- 固定定位，建议右下角或右上角。
- 支持堆叠，最多显示 3-4 条，其余按时间淘汰或排队。
- 有进入 / 离开动画，时长 100-200ms。
- 不遮挡核心表单区域；移动端改为底部居中或顶部安全区。
- 语义色低饱和，避免大面积刺眼色块。
- 当前 `App.vue` 根层级为 `z-index: 9000`，移动导航层使用 `9300`；toast viewport 建议使用 `9400+`，确保在 v2 抽屉、移动导航与普通页面内容之上。
- Toast 是真实浮层，可以使用轻量 shadow 表达 Z 轴；但卡片圆角仍收敛在 4-8px，语义色优先用于细线、图标或小面积状态，不做高饱和整块背景。

### 4.3 调用边界

- Vue 页面、v2 Pinia store、v2 composable 可以调用 toast store。
- service / data / shared 层不调用 toast。它们只返回结果、抛错或写运行日志。
- 需要写日志的错误由 v2 store / composable 捕获后调用日志服务或既有日志入口，再给 toast 短反馈。
- v2 代码禁止为 toast 反向 import `src/presentation/**`；旧 toast 只服务旧 UI 与尚未迁移的旧流程。

### 4.3.1 与静默提示开关的关系

仪表盘已有“静默提示框”开关（`toastMuteEnabled`），旧语义是减少非关键浮窗噪音。v2 toast 沿用这个用户预期，但只静默低风险提示：

- 静默：普通 `info` / `success`，例如“已保存”“已导出”。
- 不静默：`warning` / `error`。
- 不静默：填表、导入、剧情推进、正文替换、交火模式等执行链路的开始 / 失败 / 需要处理的结果。
- 不静默：带用户动作的 toast，例如“查看日志”。

如果某条成功提示在静默模式下被抑制，页面状态必须仍然能从控件、列表或当前数据变化中看出来。

### 4.4 与 `AcuMessage` 的边界

保留 `AcuMessage` 用于局部、持续、可修正或需要持续关注的信息：

- 当前提示词缺少必要占位符。
- JSON 格式错误，需要用户立即修改文件或内容。
- 当前表单字段不合法。
- 上一次执行失败后仍影响下一步操作，例如“上一次测试失败，请检查配置或查看运行日志”。
- 当前任务仍在等待用户处理的阻塞状态，例如缺少目标、缺少输入、缺少必要选择。

Toast 用于短生命周期结果，不进入面板布局。包括显式保存、导入 / 导出摘要、开始执行、执行完成、执行失败、执行取消等一次性反馈。

执行类失败可以同时产生两层反馈：

- toast：描述刚刚发生的结果，例如“测试失败，详情见运行日志”。
- `AcuMessage`：描述当前仍需关注的状态，例如“上一次测试失败，请检查配置或查看运行日志”。

## 5. 迁移顺序

本节只描述 v2 页面内部 toast 语义的迁移顺序。旧 `showToastr_ACU` 调用面、旧 runtime 全局任务、旧 toastr handle 与旧 UI fallback 不属于本轮迁移。

1. 新增 toast store 与全局 viewport，只接入 demo / 单测，不改业务页面。
   - `App.vue` 挂载 viewport。
   - store 覆盖新增、最大堆叠、自动消失、手动关闭、静默规则。
2. 接入显式保存 dirty 草稿：
   - 填表提示词保存。
   - 正文替换提示词保存。
   - 剧情推进预设保存。
3. 接入导入 / 导出结果摘要：
   - 提示词 JSON。
   - 剧情推进预设 JSON。
   - 正文替换预设 JSON。
   - API 预设 JSON。
4. 扫描并迁移局部“已保存”类 `AcuMessage`：
   - 实时保存成功提示直接移除。
   - dirty 保存成功改为 toast。
   - 可修正错误保留局部 `AcuMessage`。
   - 执行区“最后一次结果”改为 toast；若失败后需要用户持续关注，则改写为持续状态文案。
5. 与运行日志联动：
   - 复杂错误写日志。
   - 前台 toast 使用短句：`操作失败，详情见运行日志`。
6. 最后处理 custom-confirm Vue 化：
   - 删除 / 覆盖 / 清空继续使用确认弹窗。
   - 确认弹窗与 toast 共享视觉语言，但职责分离。

首批明确迁移候选：

- 仪表盘存储模式切换：`已切换到 SQLite 模式。` / `已切换到 原生 JSON 模式。` 改为 toast；失败 toast + 日志详情。
- API 预设显式保存：`已保存当前 API 预设。` 改为 toast；字段校验错误保留局部 `AcuMessage`。
- 各抽屉中的提示词显式保存、JSON 导入成功、JSON 导出成功改为 toast。
- 日志导出、数据导出、预设导出等短结果改为 toast；下载行为本身已经明显时可只保留失败 toast。

暂不迁移：

- 表单校验、缺少必要提示词插槽、JSON 格式错误等需要就地修正的信息。
- SQL 查询 / mutation 的结果区反馈。
- 手动填表、外部导入、交火索引构建等长任务的进行中进度、等待状态和阻塞原因。
- 需要持续展示或供用户复核的 warning。

需要重新梳理：

- 手动填表、外部导入、交火索引构建等长任务的完成 / 失败 / 取消结果，应迁移为 toast；面板只保留失败后仍需要用户处理的持续状态。
- 正文替换测试、重新优化等执行区结果，应把“测试完成 / 测试失败 / 已替换 N 处”迁移为 toast；失败后如需持续提示，改写为“上一次测试失败，请检查配置或查看运行日志”这类状态文案。
- 预设管理中的“已新建 / 已重命名 / 已删除 / 已切换”若界面变化已经明显，可不提示；若结果不明显或跨抽屉 / 跨页面影响状态，用 toast，而不是长期占用面板布局。

## 6. 更新参数页的目标状态

更新参数页最终应满足：

- 更新节奏、质量门槛、标签筛选的实时保存成功不 toast。
- 实时保存失败 toast：`保存失败，详情见运行日志`。
- “填表提示词”面板不显示普通设置保存消息。
- 提示词抽屉内：
  - dirty 保存成功 toast：`提示词已保存`。
  - 载入默认提示词可用局部提示或 toast：`已载入默认提示词，保存后生效`。
  - JSON 导入失败显示局部错误，并写日志。
  - JSON 导入成功 toast：`提示词 JSON 已载入，保存后生效`。

## 7. 验收标准

- 实时保存普通参数成功时没有 toast 噪音。
- 显式保存 dirty 草稿有明确完成反馈。
- 导入 / 导出 / 删除 / 执行类操作按本方案分类处理。
- 执行类操作结束后，面板内不再保留“本次已完成 / 本次失败”这类一次性结果。
- 复杂错误可在运行日志中追踪到完整详情。
- 页面内 `AcuMessage` 不再承载跨面板的“已保存”。
- 页面内 `AcuMessage` 只承载持续状态、可修正错误或需要持续关注的 warning。
- Toast viewport 在桌面和移动端不遮挡核心操作。
- 单测覆盖 store 队列、自动消失、手动关闭、最大堆叠。
- 页面集成测试至少覆盖一个保存成功 toast 与一个失败短反馈。

## 8. 后续开放点

- Toast 是否需要“查看日志”快捷按钮。
- 错误 toast 是否自动停留，还是必须手动关闭。
- 是否需要合并短时间内重复的 `已保存`。
- 是否需要为长任务提供独立任务通知，而不是普通 toast。
- custom-confirm Vue 化的具体阶段；当前允许与 toast 分阶段拆开。
