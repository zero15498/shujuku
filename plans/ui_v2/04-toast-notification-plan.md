# UI v2 Toast / 通知方案

> 状态：当前落地方案。2026-05-18 修订后，本文件可作为 v2 toast 开发依据。
> 日期：2026-05-11；修订：2026-05-18。
> 范围：定义 v2 全局通知的产品语义、调用边界、视觉约束与迁移顺序；不代表当前代码已经实现。

## 1. 背景

当前 v2 中部分页面使用局部 `AcuMessage` 显示操作结果。例如更新参数页的普通参数实时保存后，曾把“设置已保存”显示在“填表提示词”面板里。这暴露了两个问题：

- “已保存”是操作结果，不属于某个业务面板的长期状态。
- 实时保存字段如果每次都弹成功提示，会形成噪音，用户最终会忽略真正重要的反馈。

数据库已有运行日志页。通知体系应与日志流分工，而不是用 toast 承担所有错误细节。

## 1.1 当前落地修订（2026-05-18）

`SUN-1` 原文里的“下线旧 UI 前”指的是：v2 主界面已经覆盖主要功能，只剩 toast / confirm / 可视化表格编辑器等少数表层能力仍沿用旧实现的时间点。当前已经进入这个时间点，因此 v2 toast 可以先于旧 UI 删除落地。

本轮只落地 **v2 内部 toast**：

- 新增 `src/presentation-v2/stores/toast-store.ts` 与 `src/presentation-v2/components/_lib/AcuToastViewport.vue`。
- `AcuToastViewport` 挂在 `App.vue` 内，跟随 v2 根节点和 host document，不复用旧 `#toast-container`。
- `src/presentation-v2/**` 不 import `src/presentation/theme/toast`、`showToastr_ACU` 或旧 confirm 模块。
- custom-confirm Vue 化可以拆到后续阶段；toast 与 confirm 共享视觉语言，但不要求同一提交完成。
- visualizer / 可视化表格编辑器仍是单独迁移项，不阻塞 v2 toast。

本文件覆盖 v2 toast 的实现语义。旧 UI 的 `showToastr_ACU` 调用迁移、旧 toast 删除与全项目 confirm 替换，仍属于旧 UI 下线清理阶段。

## 2. 设计原则

### 2.1 不为实时保存制造噪音

实时保存的普通配置不默认 toast。控件值本身就是状态反馈。

适用例：

- 数字字段失焦保存。
- toggle / checkbox 切换。
- 下拉选择变更。
- 标签筛选规则输入。
- 世界书条目勾选。

这些操作只在失败时给前台短反馈，成功不提示。

### 2.2 Toast 只表达短、瞬时、跨页面一致的结果

Toast 用于“用户需要立即知道，但界面状态不一定自然说明”的结果。文本必须短。

适用例：

- 显式保存 dirty 草稿：`提示词已保存`、`预设已保存`。
- 导入结果摘要：`已导入 3 个预设，覆盖 1 个同名预设`。
- 导出结果：`已开始导出` 或 `导出完成`。
- 失败摘要：`操作失败，详情见运行日志`。

不适用例：

- 长错误堆栈。
- 多段业务说明。
- 表单校验说明。
- 可直接从当前页面看出的新建 / 重命名结果。

### 2.3 日志是错误详情来源，UI 是短反馈入口

警告和错误应写入运行日志流，包含完整上下文、错误对象和必要堆栈。

前台 UI 仍需要最小反馈：

- 操作失败但原因较复杂：toast 显示 `操作失败，详情见运行日志`。
- 用户可立即修正的输入问题：局部 `AcuMessage` 直接显示，例如 JSON 格式错误、提示词缺少必要占位符。
- 长耗时执行失败：执行区域显示短状态，详情进运行日志。

日志不是前台反馈的替代品；它是详细诊断来源。

### 2.4 危险操作以确认弹窗为主

删除、覆盖、清空等危险操作，首要保护是确认弹窗。成功后是否 toast 取决于结果是否明显：

- 列表立即少一项，且上下文不丢失：可不提示。
- 删除后自动切换当前项、关闭抽屉或结果不明显：可短提示。
- 删除失败：toast 短提示 + 日志详情。

### 2.5 执行类操作保留业务语义反馈

执行类操作不套用统一“已保存”。

适用例：

- 手动填表：显示本次更新结果。
- 正文替换测试：展示测试输出。
- 重新优化：说明是否替换成功、有多少建议。
- 交火构建 / 归档：显示当前任务状态。

失败详情进运行日志；执行区域应显示任务是否结束与简短结果。

## 3. 操作分类规则

| 操作类型 | 成功 toast | 失败前台反馈 | 详情位置 | 备注 |
|---|---|---|---|---|
| 实时保存普通参数 | 否 | 是 | 运行日志 | 控件状态已表达成功 |
| 显式保存 dirty 草稿 | 是 | 是 | 局部 message / 运行日志 | 需要“未保存 -> 已保存”闭环 |
| 新建 | 通常否 | 是 | 运行日志 | 若直接进入编辑或列表可见，不提示 |
| 重命名 | 通常否 | 是 | 运行日志 | 名称立即变化即可 |
| 删除 | 视情况 | 是 | 运行日志 | 确认弹窗是主要保护 |
| 导入 | 是 | 是 | 局部 message / 运行日志 | 需要摘要数量、覆盖数量 |
| 导出 | 可选 | 是 | 运行日志 | 下载行为明显时可不提示 |
| 执行业务任务 | 各自实现 | 是 | 运行日志 | 不使用通用“已保存” |
| 表单校验 | 否 | 局部显示 | 当前表单 | 用户需要立即修正 |

## 4. 推荐架构

### 4.1 全局 store

新增 v2 专用通知 store，例如：

- `src/presentation-v2/stores/toast-store.ts`

状态建议：

- `items: ToastItem[]`
- `ToastItem`: `id`、`kind`、`text`、`createdAt`、`durationMs`、`dismissible`、可选 `action`

动作建议：

- `success(text: string, options?)`
- `info(text: string, options?)`
- `warning(text: string, options?)`
- `error(text: string, options?)`
- `dismiss(id: string)`
- `clear()`

默认时长：

- success / info：约 2200-3000ms。
- warning：约 4000ms。
- error：约 5000ms 或手动关闭。

### 4.2 全局渲染位置

新增全局组件，例如：

- `src/presentation-v2/components/_lib/AcuToastViewport.vue`

挂载位置：

- `App.vue` 或 root shell 内，位于主内容与抽屉之上。

视觉要求：

- 固定定位，建议右下角或右上角。
- 支持堆叠，最多显示 3-4 条，其余按时间淘汰或排队。
- 有进入 / 离开动画，时长 100-200ms。
- 不遮挡核心表单区域；移动端改为底部居中或顶部安全区。
- 语义色低饱和，避免大面积刺眼色块。
- 当前 `App.vue` 根层级为 `z-index: 9000`，移动导航层使用 `9300`；toast viewport 建议使用 `9400+`，确保在 v2 抽屉、移动导航与普通页面内容之上。
- Toast 是真实浮层，可以使用轻量 shadow 表达 Z 轴；但卡片圆角仍收敛在 4-8px，语义色优先用于细线、图标或小面积状态，不做高饱和整块背景。

### 4.3 调用边界

- Vue 页面、v2 Pinia store、v2 composable 可以调用 toast store。
- service / data / shared 层不调用 toast。它们只返回结果、抛错或写运行日志。
- 需要写日志的错误由 v2 store / composable 捕获后调用日志服务或既有日志入口，再给 toast 短反馈。
- v2 代码禁止为 toast 反向 import `src/presentation/**`；旧 toast 只服务旧 UI 与尚未迁移的旧流程。

### 4.3.1 与静默提示开关的关系

仪表盘已有“静默提示框”开关（`toastMuteEnabled`），旧语义是减少非关键浮窗噪音。v2 toast 沿用这个用户预期，但只静默低风险提示：

- 静默：普通 `info` / `success`，例如“已保存”“已导出”。
- 不静默：`warning` / `error`。
- 不静默：填表、导入、剧情推进、正文替换、交火模式等执行链路的开始 / 失败 / 需要处理的结果。
- 不静默：带用户动作的 toast，例如“查看日志”。

如果某条成功提示在静默模式下被抑制，页面状态必须仍然能从控件、列表或当前数据变化中看出来。

### 4.4 与 `AcuMessage` 的边界

保留 `AcuMessage` 用于局部、持续、可修正的信息：

- 当前提示词缺少必要占位符。
- JSON 格式错误，需要用户立即修改文件或内容。
- 当前表单字段不合法。
- 当前执行区的最后一次任务结果。

Toast 用于跨页面的短生命周期结果，不进入面板布局。

## 5. 迁移顺序

1. 新增 toast store 与全局 viewport，只接入 demo / 单测，不改业务页面。
   - `App.vue` 挂载 viewport。
   - store 覆盖新增、最大堆叠、自动消失、手动关闭、静默规则。
2. 接入显式保存 dirty 草稿：
   - 填表提示词保存。
   - 正文替换提示词保存。
   - 剧情推进预设保存。
3. 接入导入 / 导出结果摘要：
   - 提示词 JSON。
   - 剧情推进预设 JSON。
   - 正文替换预设 JSON。
   - API 预设 JSON。
4. 扫描并迁移局部“已保存”类 `AcuMessage`：
   - 实时保存成功提示直接移除。
   - dirty 保存成功改为 toast。
   - 可修正错误保留局部 `AcuMessage`。
5. 与运行日志联动：
   - 复杂错误写日志。
   - 前台 toast 使用短句：`操作失败，详情见运行日志`。
6. 最后处理 custom-confirm Vue 化：
   - 删除 / 覆盖 / 清空继续使用确认弹窗。
   - 确认弹窗与 toast 共享视觉语言，但职责分离。

首批明确迁移候选：

- 仪表盘存储模式切换：`已切换到 SQLite 模式。` / `已切换到 原生 JSON 模式。` 改为 toast；失败 toast + 日志详情。
- API 预设显式保存：`已保存当前 API 预设。` 改为 toast；字段校验错误保留局部 `AcuMessage`。
- 各抽屉中的提示词显式保存、JSON 导入成功、JSON 导出成功改为 toast。
- 日志导出、数据导出、预设导出等短结果改为 toast；下载行为本身已经明显时可只保留失败 toast。

暂不迁移：

- 表单校验、缺少必要提示词插槽、JSON 格式错误等需要就地修正的信息。
- SQL 查询 / mutation 的结果区反馈。
- 手动填表、外部导入、交火索引构建等长任务进度和最终业务结果。
- 需要持续展示或供用户复核的 warning。

## 6. 更新参数页的目标状态

更新参数页最终应满足：

- 更新节奏、质量门槛、标签筛选的实时保存成功不 toast。
- 实时保存失败 toast：`保存失败，详情见运行日志`。
- “填表提示词”面板不显示普通设置保存消息。
- 提示词抽屉内：
  - dirty 保存成功 toast：`提示词已保存`。
  - 载入默认提示词可用局部提示或 toast：`已载入默认提示词，保存后生效`。
  - JSON 导入失败显示局部错误，并写日志。
  - JSON 导入成功 toast：`提示词 JSON 已载入，保存后生效`。

## 7. 验收标准

- 实时保存普通参数成功时没有 toast 噪音。
- 显式保存 dirty 草稿有明确完成反馈。
- 导入 / 导出 / 删除 / 执行类操作按本方案分类处理。
- 复杂错误可在运行日志中追踪到完整详情。
- 页面内 `AcuMessage` 不再承载跨面板的“已保存”。
- Toast viewport 在桌面和移动端不遮挡核心操作。
- 单测覆盖 store 队列、自动消失、手动关闭、最大堆叠。
- 页面集成测试至少覆盖一个保存成功 toast 与一个失败短反馈。

## 8. 后续开放点

- Toast 是否需要“查看日志”快捷按钮。
- 错误 toast 是否自动停留，还是必须手动关闭。
- 是否需要合并短时间内重复的 `已保存`。
- 是否需要为长任务提供独立任务通知，而不是普通 toast。
- custom-confirm Vue 化的具体阶段；当前允许与 toast 分阶段拆开。
